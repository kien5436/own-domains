# Linux `.deb` Packaging Plan (Milestone E3)

## Goal

Build a Tauri `.deb` bundle of the desktop app (GUI + daemon + CLI + Linux sidecars) on the Ubuntu VM, install it, run privileged setup, and verify the full runtime — then document the install/uninstall flow.

## Constraints

- Bundle contents reuse the existing seams: `tauri.conf.json` `externalBin` (`binaries/own-domains-daemon`, `binaries/own-domains`) staged by `scripts/stage-desktop.ts`, and `resources` already mapping both Linux sidecar layouts. No new binary plumbing.
- Config change is additive: add `"deb"` to `bundle.targets` plus only the metadata the Tauri schema requires for deb (keep `app` for dev). No macOS/Windows bundle output changes.
- Setup still runs explicitly post-install (`sudo own-domains setup --apply …`); the package does not auto-enable units or run privileged steps in maintainer scripts. Uninstall is `own-domains uninstall --apply [--purge]` then `dpkg -r`.
- The GUI already runs under WSLg per the milestone-2 notes; this plan covers native Ubuntu 24.04 x86_64 (ARM64 build is the same flow with `--target`, attempted only if time permits on the VM).
- No auto-updater, no repository hosting, no `postinst` unit enablement. Those are release-engineering follow-ups.

## Out of Scope

Docker detection, global `~own` check (separate plan), `.rpm`/AppImage, Windows NSIS changes, auto-updates, apt repository.

## Verification Commands

- config: `python3 -c "import json; json.load(open('crates/own-domains-desktop/tauri.conf.json'))"` from `/Users/kien/workspace/domains`
- host: `cargo check -p own-domains-desktop` (as far as it goes on macOS) and `pnpm exec tsc` per repo scripts if applicable
- VM (the real verification): dependency install, `cargo build --release`, `stage-desktop.ts --release`, `tauri build --bundles deb`, `dpkg -i`, setup, runtime + doctor checks, `dpkg -r`

### Task 1: Survey Linux bundle gaps

Files: read-only (`crates/own-domains-desktop/tauri.conf.json`, `scripts/stage-desktop.ts`, `crates/own-domains-desktop/src/*.rs`, `package.json` desktop scripts).

Gap checklist (surveyed 2026-11-08, to be confirmed before Task 2):

1. `bundle.targets` is `["app"]` — no `"deb"` target. The `macOS` bundle section exists; no `linux`/`deb` bundle config at all.
2. Missing recommended deb metadata: no `category`, no `shortDescription`/`longDescription` (Tauri fills defaults, but store-quality strings should be set deliberately).
3. Icons: only `icon.ico` + `icon.png` exist. A Linux bundle wants `32x32.png`, `128x128.png`, `128x128@2x.png` (generate via `tauri icon` from the present source PNG).
4. No `desktop:build:linux` npm script. Existing pattern to mirror: `desktop:build:windows` (`cargo build --release --target <triple> -p … && tsx scripts/stage-desktop.ts --release --target <triple> && tauri build --target <triple> --bundles deb`), with the Linux triple `x86_64-unknown-linux-gnu`. ARM64 is explicitly out of scope for this slice.
5. All Linux verification runs on the Ubuntu VM (x86_64); WSL is fallback only.
6. `stage-desktop.ts` already handles non-Windows triples generically (no `.exe` suffix for Linux) and sidecar resources for both Linux triples are already in `tauri.conf.json` — no changes expected there, to be confirmed by a real build.
7. Unknowns for the VM run: exact `apt install` set for Tauri v2 on Ubuntu 24.04, and whether the headless `tauri build --bundles deb` needs a display (the app already ran under WSLg per the milestone-2 notes, which de-risks startup substantially).
8. The desktop Rust crate compiles for macOS/Windows today; a Linux compile is unproven on stable toolchains in this repo.

Done when: this checklist is reviewed in chat and any corrections are folded back into the plan before Task 2.
